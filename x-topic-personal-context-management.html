一、范式层：同一个循环的三次放大

自回归 → agent 循环 → 人的学习

你昨天提炼的同构关系在 X 上有完整谱系，而且被推得更远。

「1 次 GPT 调用有点像 1 个念头。把它们串进循环，就造出了能感知、思考、行动的 agent，目标用英语写在提示里。至于反馈/学习，一条路径是加一个『反思』阶段评估结果、把轨迹存进记忆、再加载回提示里做 few-shot。你能『学到』的，就是你能塞进上下文的东西。」@karpathy · 2023-04
「LLM 有点像一个患顺行性遗忘症的同事——训练结束后不再巩固任何长期知识，只有短期记忆（上下文窗口）。跟这种状况的人建立关系（见《初恋 50 次》）或者做事（见《记忆碎片》）都很难。」@karpathy
「遇到问题、搞明白、然后用相当明确的措辞『记住』点什么留给下次。比如『看来碰到这类问题时，我应该试试那类办法』。这感觉更像给自己记笔记。……知识引导的『复盘』阶段，是比标量奖励高得多维的反馈通道。」@karpathy · system prompt learning
对你的含义 你要管的「个人上下文」，在这个框架里就是你自己的 system prompt 语料库。个人事实只是最浅一层，真正复利的是策略层——而这一层恰好最难被通用记忆功能自动抽取，必须你有意识地写下来。

个人身份层的实操版：三小时搭完，六周见效

建 brain/ 目录：USER.md（姓名、时区、作息、履历、兴趣、雷区，约 80 行）、MEMORY.md（决策、教训、观点，每次会话都读并追加）、family/{名字}.md（一人一文件）。

别自己憋把 onboarding 提示词丢给 agent，回答 10-15 分钟的问题，让它生成全部文件。
每日一滴灌设 9 点定时任务：「读我的 USER.md 和家庭文件，找出一个空白，就此问我一个深思熟虑的问题」。你 30 秒回答，第二天它处理答案、更新文件、再问新问题。
第 1 天：一个做了好笔记的陌生人。第 2 周：开始有点私人感。第 6 周：一个真懂你的助手。「没有向量库，没有花哨 RAG，就是 markdown 文件加每天一个问题。」@coreyganim
流程层用 skill，不要用提示词
「一个 skill 就是一个含 SKILL.md 的文件夹——名字、描述、纯英文步骤。描述是最多人写错的部分：它决定何时触发，要像规则那样写，不要像标题那样写。你甚至不用自己写，让 Claude 就这个任务访谈你、再让它起草，十分钟一次性搞定。之后输出漂了就改 skill 一次，而不是永远改每条提示词。每周一个 skill，到 12 月你就攒出了一支团队。」@AISystems_hq
易被忽略「把你的『永远不要做 X』规则写成权限设置，而不是 CLAUDE.md 里的句子——长会话里那些句子会被忽略。」@EXM7777

格式之争在收敛2026-09-18 起 Claude Code 支持 AGENTS.md：文件夹里没有 CLAUDE.md 时就读它（@trq212 · 23,234♥）。对你的含义：新建个人上下文文件优先用 AGENTS.md，跨工具可移植性最好——Karpathy 自己的知识库 schema 也放在 AGENTS.md 里。

四、减法一侧：上下文是预算，不是仓库

Anthropic 官方的新规则

六、反方：为什么「多存」会反噬

✅ 支持建体系

Karpathy 本人跑 40 万词知识库，Lex Fridman 跑同构系统
「人读、模型写」把维护成本压到接近零
输出回填让每次使用都增值，形成复利

⚠️ 反对/警告

记忆会分散模型注意力，Karpathy 原话「有点像用力过猛」
模型会对被 RAG 进来的零碎记忆过拟合
人工维护的第二大脑会变成「第二份工作」
上下文体系本身正在变成一种表演（600 行 CLAUDE.md）
为旧模型写的规则会变成新模型的负担
最硬的一条反方证据，来自 Karpathy 自己（2 万赞）
「所有 LLM 的个性化都有一个通病：记忆对模型来说似乎非常分散注意力。两个月前问过一次的某个话题，会被当成我某种深度兴趣不断冒出来、永远被无端提及。有点像用力过猛。」@karpathy · 20,949♥
「我轮着用所有 LLM，都这样，所以这不是某个实现的问题，而是更深层的东西——也许训练时上下文窗口里的信息大多与任务相关，于是 LLM 养成了『用给我的东西』的偏好，到测试时就对任何碰巧被记忆功能 RAG 进来的东西过拟合。」@karpathy
对你的含义 往上下文里塞得越全，越可能招来「用力过猛」的联想。这直接反对「把一切个人信息都塞进常驻记忆」的路线，支持「默认精简 + 按需加载」的分层结构。

给你的方法论草案 （综合推断，非某位大佬原话）

分四层，各有各的生命周期和加载时机
L0 身份层
AGENTS.md / USER.md，50-80 行。只写模型「看一眼环境学不会、但每次都会踩」的东西：你是谁、默认语言与风格、指令优先级、几条硬边界。是坑清单，不是简历
常驻·极小
L1 索引层
MEMORY.md，一行一条列出所有二级文件。这是「随取随用」的核心开关：让「全都存着」和「不全都喂」同时成立
常驻
L2 领域层
按领域一个文件，绝不按日期。镜像外部系统的标 last_sync 并声明为 cache
按需加载
L3 流程层
skills。判定规则：本月重复解释超过三次 → 建一个 skill；触发描述写成规则而非标题
触发式
两个循环让它自己长大
编译循环（对应 raw → wiki）：所有输入先无脑落 raw/ 不做整理（降低摄入摩擦是所有 PKM 存活的前提）；定期让 agent 增量编译进 wiki。人只读，模型只写——这是避开「第二份工作」陷阱的唯一已知解法。产出物回填 wiki，让每次使用都增值。
蒸馏循环（对应 system prompt learning）：定期让 agent 扫你的会话记录，把「我反复纠正它的地方」提炼成 L0/L1 的新条目。这是 Karpathy 说的「给自己写的那本解题书」，复利最高、最不可能被通用记忆功能自动学会。
三条守恒定律
注意力守恒
加进常驻层的每一行，都在跟你未来所有请求抢注意力。默认答案是「放进 L2 按需加载」，不是「放进 L0」
克制
季度清零
模型在进化，为旧模型写的补丁会变成新模型的负担。用 /context、/doctor、prompt-audit 做定期体检
定期删
隔离写入
给 agent 一个独立的写入区，别让模型生成的内容污染你的主库（kepano 的提醒）
隔离
关于你的 LLM wiki 试点 从证据看方向是对的（Karpathy、Lex Fridman 都在跑同构系统）。它「感觉不是终极解法」的原因很可能不在 wiki 本身，而在缺了 L0/L1 这两层薄的、常驻的接口——wiki 解决了「知识存在哪」，但没解决「每次对话开场，模型默认知道我是谁、这次该加载哪一块」。先补索引层，再谈换架构。（推断）

方法与局限

  • 内容农场噪音严重。本主题（尤其「Karpathy 第二大脑」）是今年被搬运最多的题材之一，数十个账号逐字复制同一段文案，Graphify 相关文案至少见于 6 个账号且星标数互相矛盾（7.6 万 ~ 14.8 万）。报告中一手观点均已追到原作者，转述型已显式标注。
  • 样本偏英文圈。中文检索式仅 4 条且热度门槛被迫放低（min_faves 20-50）；中文圈观点基本是英文圈的转述与本地化，未见独立方法论创新。
  • 限流影响。首批 10 条检索式中 5 条被 X 拒绝（嵌套括号过多），简化语法后重跑；简化会损失精确匹配，可能漏掉长尾观点。批量脚本另有一次 UnicodeDecodeError 崩溃（输出截断于 64KB），改用逐条调用后解决。
  • 数字类结论普遍不可靠。涉及百分比的三处（80% 系统提示削减、73% token 浪费、context rot 80%→36%）只有第一处有 Anthropic 官方长文背书，另两处均为二手转述。
  • 未覆盖：论文原文、Anthropic/OpenAI 官方工程博客原文、GitHub 仓库实测均未核验；本报告只反映 X 上的讨论。
